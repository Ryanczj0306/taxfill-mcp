## Context

ADR-0001 chose a guarded no-pack fallback and left its MCP surface to this ADR. Facts at ccf02d2:

- The server registers 23 tools. Every fetch, fill and verify tool starts at `_load_any_pack` (server.py:182-196). That function already routes a second pack kind, the hand-fill pack, through the same tools "without a 24th tool" (server.py:188). verify_form then returns a second verdict shape with its own `limits` (server.py:326-336, built at :150-179). test_overlay_tools.py:54-55 pins the count at 23.
- `render_form` renders any PDF with no pack (server.py:411-423). The vision check needs no change.
- The pack-free building blocks exist as core functions: `fetch_blank` with `sha256=None` (fetch.py:335-441), `extract_fields` (packbuild.py:67-94), `sentinel_sweep` (packbuild.py:187-221), `locate_labels` (overlay.py:918-973), `clipping_scan` (verify.py:1455), `regression_diff` (verify.py:1854-1867), `widget_flag_problems` (verify.py:2363-2395), and the content-stream writer the overlay stamps with (overlay.py:282-287, :325-351, :659-661).
- KG8 freezes pack-path output from 2026-12-01 to 2027-04-15. It allows additive, opt-in, unmapped-only parameters and fields if the JK21 golden diff of every pack-path response stays byte-identical. JK16 and JK17 may land inside the freeze.
- JK21's harness snapshots only the tools that read state knowledge (scripts/golden_snapshots.py:2-25). It does not snapshot fetch_blank, get_form_map, fill_form, verify_form or verify_filing.

## Decision

Option A. The fallback rides fetch_blank, get_form_map, fill_form and verify_form. The tool count stays 23. Option B's main advantage, untouched pack tools, is matched by the routing rules below and by JK14's pack-path golden.

### Routing rules for the four tools

1. `form="unmapped"` is the only switch. Each tool tests it first and returns from its own unmapped branch before `_load_any_pack` runs (server.py:244, :275, :325) or `_get_form_map` runs (server.py:231). The pack branch keeps its code.
2. "unmapped" is a reserved key. A gate test fails if a directory formpacks/<jurisdiction>/<year>/unmapped/ exists.
3. Every new parameter defaults to None. With a pack key, any new parameter is refused ("only for form='unmapped'"). It is never ignored in silence.
4. Every unmapped response carries `grade: "unmapped_draft"`, `limits` and `next_step` at its top level. The values worksheet carries its own `grade`, because an agent may pass it on alone. No pack-path response gains a `grade` key. The JK6 guard already fails a pack step that carries grade "unmapped_draft" (test_journeys.py:172-173, :176-182). The new response-shape test fails a pack response with any `grade` key.
5. Every step after the fetch names the blank by `blank_sha256`. A URL alone is not enough: rotating "current" URLs serve new bytes over time (rule 6).
6. A refusal raises ValueError, as the pack path does (server.py:248, :281-286). It says that no PDF was written and names a pointer: the official URL, the agency's forms page, or a get_sources topic. It never echoes a value (the rule of server.py:199-209) or the data directory's absolute path (JK27).
7. Response text that names filing-grade puts "not" or "never" right before it ("NOT FILING-GRADE", "never filing-grade"). The same holds for "ready to file", "ready to sign", "ready to mail", "ready for filing" and "is final". The JK6 guard flags any other wording (test_journeys.py:118-122, :146-148). It also flags a `status` of "final" or "ready" (:138-140).
8. The unmapped branches import taxfill_core.overlay lazily, inside the branch, as server.py:246, :277, :333 and :390 do. test_overlay_tools.py:58-64 fails if importing the server loads that module.

### fetch_blank

- New parameters: `source_url: str | None`, required with `form="unmapped"`. `form_title: str | None`, required: the form's printed name as the request expects it, for example "SD 100". `local_blank: str | None`, optional: a PDF the user saved from `source_url` (rule 5).
- Unmapped response: `grade`, `path`, `source_url`, `sha256` (recorded, not pinned), `pinned: false`, `origin` ("download" or "local_blank"), `fetched_at`, `first_page` (`page`, `printed_year`, `title_found`; rule 7), `page_count`, `kind` ("acroform", "acroform_xfa_hybrid", or "flat" for a blank with no widget, rule 10), `limits`, `next_step`.
- A download goes to a separate unmapped namespace of the blank cache, keyed by sha256. A local blank goes under the year's workspace instead (the root the server resolves at server.py:96; workspace.py:123), so `taxfill purge` removes it with the year's drafts (workspace.py:330-341; cli.py:93-104). A record beside the bytes holds source_url, year, jurisdiction, form_title, fetched_at, origin and the rule-7 result. It holds no field value. Refusal rules 1-9 and 11 run here; rule 10 applies at get_form_map and fill_form.

### get_form_map

- New parameters: `source_url` and `blank_sha256`, both required with `form="unmapped"`.
- Unmapped response: `grade`, `form: "unmapped"`, `jurisdiction`, `tax_year`, `source_url`, `blank_sha256`, `fields`, `hand_write`, `sweep_path`, `anchor_basis`, `limits`, `next_step`.
- Each `fields` entry: `name` (the qualified field name), `kind` (text, checkbox, radio, choice, signature or pushbutton), `tooltip` (/TU), `maxlen`, `comb`, `multiline`, `options` (/Opt), `on_states`, `fillable`, `refusal` (null, or why the field is never filled: read_only, pushbutton, viewer_guard, signature or calculated), `widgets` and `confidence`. Each `widgets` entry gives `page`, `rect` and `anchor` (`printed_line`, `label`, `confidence`).
- One value fills every widget of its field. Measured: 291 text fields, on 88 cached blanks, have more than one widget, and 245 of them span pages, on 82 blanks. So anchoring is per widget, and a field's `confidence` is the lowest of its widgets'.
- `confidence` is one of "anchored (unverified line map)", "med", "low" or "none". The string "high" is never emitted.
- `sweep_path` is a stamped copy of the blank, written beside it, in which each fillable field shows its index ("#12") on every one of its widgets, the way `sentinel_sweep` shows field names to pack authors (packbuild.py:187-221). The agent shows it with render_form so the user can confirm boxes (KG11). It holds no user data, because rule 5 refuses a local blank that holds a typed value.
- `anchor_basis` names the committed JK15 table the tiers rest on, or says that no table has passed, so only "low" and "none" are emitted.

### fill_form

- `values` is keyed by qualified field name (for a flat blank, see the worksheet-only response).
- New parameters: `source_url` and `blank_sha256`, required. `money_fields: list[str] | None`: whole-dollar rendering applies only to these fields. `provenance: dict[str, str] | None`: per field, "from a document" or "from the user", recorded beside the KG7 label; it never removes the label. `confirmed_fields: list[str] | None`: fields whose boxes the user confirmed on the sweep page (KG11).
- PDF response: `grade`, `status: "unverified_draft"`, `out_path`, `output_sha256`, `written` (field to rendered value, as on the pack path), `hand_write` (field, page, printed_line, label, value, reason), `labels` (per written field: "agent-computed, unverified", plus any declared source), `confirmed` (per field, recorded as "user-confirmed on the rendered page"), `stamp` (text and pages), `worksheet` (`grade`, then lines ordered by page and printed line, each with its label), `warnings`, `guards_hidden`, `limits`, `next_step` (verify_form with `form="unmapped"`, then render_form on every page).
- Worksheet-only response: with no passing JK15 table (KG6), and for a flat blank (rule 10), fill_form writes no PDF. It returns `grade`, `status: "worksheet_only"`, `worksheet` (ordered by page and printed line, with get_form_map's anchors), `hand_write` (every value), `labels`, `limits` and `next_step`. A flat blank has no fields, so there `values` is keyed by the printed line as the agent reads it, rule 14's field-name check does not apply, and the worksheet says that no line was matched to a box.
- The output PDF carries a document record, `/TaxfillUnmapped` in its /Info dictionary: the grade, source_url, blank_sha256, the written field names, their labels and declared sources, and the confirmations. It holds no values.
- The PDF is written once, already stamped. No unstamped copy reaches disk.

### verify_form

- New parameters: `source_url` and `blank_sha256`, required. `declared_relations: list[str] | None`: relations over field names that the agent declares; each is checked and labeled "agent-declared, not of record".
- Existing parameters in unmapped mode: `expected` is required and is fill_form's `written` map. `independent` is keyed by field name.
- Unmapped response: `grade`, `verdict: "UNMAPPED"`, `ok` (true only when every section passes), `output_sha256`, `verified_at` (only when ok: the output's sha256 and the time; any later change to the file voids it), `sections`, `unverified_values` (every written field with its KG7 label; `ok` removes none), `hand_write`, `limits`, `next_step`. It carries no `status`: `ok` and `verified_at` say what passed, and the grade stays "unmapped_draft".
- `sections`, each with checked, failed and failures: `record` (the /Info record agrees with the call; added in JK17), `round_trip` (exactly the written names read back), `unchanged` (regression_diff against the blank: nothing else changed), `clipping` (P-001), `flags` (P-027), `stamp` (every page, KG5), `anchors` (the KG11 re-check, per widget), `recompute` (`independent`; a match is reported here and changes no label), `declared_relations`.
- `limits` is a module constant, a list like OVERLAY_VERDICT_LIMITS (overlay.py:219-230): no line map; no relations of record; no identity or cross_form checks; no P-003 required-checkbox audit; no revision pin; form scripts and XFA bindings did not run; every value is agent-computed and unverified. Its last entry says that ok means only the listed checks passed, and that the draft is never filing-grade.

### The other tools

- list_forms, render_form, hand_fill_worksheet and the other tools do not change. render_form returns images, and the stamp is in them.
- verify_filing is not ridden. An item whose form is "unmapped" is refused with a pointer to verify_form (rule 15). An unmapped draft takes no part in cross-form identity checks.

### What stays byte-identical for packs

- Called without the new parameters, with any form key other than "unmapped", on any input that is not fallback output, each of the four tools and verify_filing returns what it returns at ccf02d2: the same keys, values, errors and messages, and the same field values in the written PDF. The two exceptions are deliberate. Today form "unmapped" fails with "no form pack for form 'unmapped'" (discovery.py:48-52, :208-215); after routing rule 1 it reaches the unmapped branch. Rule 15 refuses fallback output on the pack path.
- JK14 adds a pack-path golden before the first unmapped branch merges, because JK21's harness does not cover these tools. It pins get_form_map over every shipped pack and today's refusal texts, offline. The data root is replaced as JK21's harness does (scripts/golden_snapshots.py:346-349), and the cache and temporary output paths are replaced the same way. It pins fetch_blank, fill_form, verify_form and verify_filing offline through the real `_load_any_pack` and `fetch_pack_blank`. A synthetic demo pack sits under a temporary TAXFILL_DATA_DIR (datadir.py:25). Its synthetic blank is seeded into a temporary TAXFILL_BLANKS_CACHE (fetch.py:53) under the cache name for its source_url (fetch.py:168-177), where fetch_blank finds it by digest with no download (fetch.py:405-407). Nothing is stubbed. The golden pins no call with form "unmapped". This offline golden is the KG8 gate. The real-blank fill and verify steps run in the network job (.github/workflows/freshness.yml:50-81), which monitors and does not gate (.github/workflows/ci.yml:6-8). The freeze section says how a PR uses it.
- Each tool's tools/list entry keeps every existing property's name, type, default and required status. New optional properties, with their own descriptions, are the additive change KG8 allows. A change to existing description text is not (see The freeze).
- No tool count or tool list moves (Open question 3).

## Refusal rules

Rules 1-14 apply only with `form="unmapped"`. Rule 15 keeps fallback output out of the pack checks. These parts are additions to the JK13 and JK14 lists: rules 1, 10, 11, 14 and 15; the HTTPS and per-hop parts of rule 2; the typed-value check of rule 5; the /NeedsRendering part of rule 8; and the signature part of rule 12. The viewer-guard part of rule 12 comes from the JK16 box (docs/dev/ROADMAP.md:353). Each rule follows from the code fact named in it.

1. **A shipped pack wins.** Refuse when `source_url` equals the source_url of a shipped pack or hand-fill pack for the requested jurisdiction and year, or when the fetched bytes' sha256 equals a shipped pack's pdf_sha256. Refuse too when that jurisdiction and year have a shipped or hand-fill pack whose printed form name (FormSummary.form, discovery.py:84) equals the normalised `form_title`, whatever the URL. The comparison uses rule 7's normalisation and drops a leading "Form" and the jurisdiction's postal code from both names, so "MA Form 1" and "Form 1" match. For an irs.gov URL it also compares the file name, without a "--<year>" or "--dft" suffix, with the pack's. The refusal names the pack's form key. For a planning-only year it says that the pack refuses that year until the finals are pinned. Example: the TY2026 Form 1040 pack is pinned to irs-dft/f1040--dft.pdf (formpacks/federal/2026/f1040/pack.yaml:63, :65), so a final posted at irs-pdf/f1040.pdf matches it by name and by file name, though not by URL. Refuse an IRS early-release draft too (a URL under irs.gov/pub/irs-dft/): the pack path fills a draft only in core rehearsal mode (filler.py:663-666, :678-681; discovery.py:124-128). Without this rule the unmapped path would route around a pack's own refusals, such as a planning-only year (knowledge.py:2724-2757; :2730 says "Refuse to let a planning-only pack back a filed return"), or around a byte-different re-serve of a pack's own revision (docs/dev/HISTORY.md:1988). *Enforced in:* JK14 (fetch), re-checked in JK16 (fill). *Extends:* discovery.list_forms (discovery.py:132-181), which carries each pack's form and source_url, plus the hand-fill packs it does not list (discovery.py:56-73). *Implemented in JK16 (2026-10-25), stricter than written:* the URL, the IRS file name and a title that carries a state's postal code are matched whatever jurisdiction the caller claims, the URL ignoring scheme, query and a leading "www.", and a bare federal main-form title (1040, 1040-SR, 1040-NR, 1040-X) is the federal pack's under any state claim, after the claimed jurisdiction's own packs; the name is normalised before "Form" and the postal code are dropped, so "IL 1040" matches "Form IL-1040".
2. **Official host, HTTPS, every hop.** `source_url` must be https. fetch_blank also accepts http and file:// (fetch.py:372-378); the unmapped path does not. The host must pass `is_official_gov_host` (knowledge.py:41-53), the rule fetch_blank applies today (fetch.py:394-399): .gov, .mil or *.state.<xx>.us. The unmapped fetch uses its own opener whose redirect handler checks each Location before requesting it (https and is_official_gov_host). A failing hop is never requested, and the fetch is refused with a pointer. The final URL is checked too. Today `_download` follows every redirect before anything is checked (fetch.py:240-249), although the server promises outbound traffic only to the agencies' sites (server.py:5-8) and fetch.py gives SSRF as the reason for the host rule (fetch.py:380-384). On the pack path a pinned digest covers the bytes; the unmapped path has no digest. *Enforced in:* JK14. *Extends:* fetch.py:372-399 and :240-249, in an unmapped-only function, so the pack branch does not change.
3. **Pinned-only hosts.** A host in PINNED_ONLY_BLANK_HOSTS (fetch.py:103-109; today New Mexico's document API) is refused without a pinned sha256 (fetch.py:388-393). The unmapped path never has one. It refuses with a pointer to the agency's forms page and offers rule 5. *Enforced in:* JK14. *Extends:* fetch.py:388-393, stated and not bypassed.
4. **Hosts that refuse scripts.** A 401 or 403 answer raises RefusedFetchError (fetch.py:224-232). A Wayback mirror is then used only digest-verified (fetch.py:277-278). The unmapped path has no digest and accepts no caller-supplied mirror. It refuses with a pointer and offers rule 5. MA Form 1 2024 is the JK19 refusal case. *Enforced in:* JK14; JK19 checks it. *Extends:* fetch.py:273-296.
5. **A user-supplied local blank passes the same checks.** `local_blank` names a PDF the user saved from `source_url`. It must carry %PDF in its first 1024 bytes, as seed_blank checks (fetch.py:313-314). The `source_url` host must be official or listed in PINNED_ONLY_BLANK_HOSTS. Rule 7 then stands in for the pin, as the JK14 box says. The blank must hold nothing the user typed. It is refused if any field that is neither ReadOnly nor calculated carries a /V that differs from its /DV, except a text or choice value made only of zeros, spaces and punctuation. The refusal gives a count, never a value. Measured on the 344 distinct cached blanks: this refuses 2 official blanks, AL 40NR 2023 and WV IT-140 2023, which preset a checkbox or radio state. Without the exception it would refuse 9, adding NJ 1040 and MO-1040 for three years each and WV IT-140 2024, which preset "0", "." or ", ". The bytes are stored under the year's workspace, not in the shared blank cache (fetch.py:121-146), so `taxfill purge` removes them. seed_blank itself is not reused, because it needs a pack digest (fetch.py:311). *Enforced in:* JK14. *Extends:* seed_blank's checks (fetch.py:305-322), without the digest.
6. **The cache is never trusted and never shared with packs.** With `sha256=None`, fetch_blank returns any cached file for the URL (fetch.py:405-407). The unmapped path downloads every time. It stores the bytes in its own namespace, keyed by sha256 (a local blank goes under the workspace, rule 5); the pack cache is keyed by URL alone (fetch.py:168-177). It never overwrites a pack's cache entry. Verify reads that entry offline to consult a pack's pinned blank (verify.py:1589-1599). A foreign file there counts as absent, and pack-path verify then scans every mapped ReadOnly widget without the blank (verify.py:115-118). That can change pack-path output. Later steps load the blank by `blank_sha256`. They refuse a digest that is missing, or whose record disagrees with (source_url, year, jurisdiction). Rotating URLs make this necessary: the IL-1040 "currentyear" path re-served the same revision as a different byte stream in 2026 (docs/dev/HISTORY.md:1988), and the OK 511 "current" slot will serve TY2026 (docs/dev/HISTORY.md:1998). *Enforced in:* JK14. *Extends:* fetch.py:402-408 and :439-441.
7. **The form's first page must match the request.** The check reads the form's first page: the first page that carries a widget, or page 1 when none does, because a packet can open with instructions (Open question 16). Its title block is the top third of that page, inside the visible box. The tax year is the year printed tallest in the title block, by glyph height. It must equal the requested year, and no other year may be printed at 80% of that height or more. On the measured blanks, due dates, fiscal-year entries and prior-year references print smaller than the tax year, so they do not count. `form_title` must appear in the title block as a whole token sequence, ignoring case, spaces, hyphens and line breaks. The check runs on every copy served, cached or fresh. Today a person does this step (fetch.py:14-19, :429-437). A revision-dated form that prints no tax year fails it (Open question 7). Measured over the 267 packs that are not IRS drafts (every one of the 298 packs has its blank in the cache): the year test passes 241. It refuses the 18 whose form is revision-dated, and 8 whose title block has no year in its text layer (FinCEN Form 114 for four years, DC D-40 for three, and the NM PIT-1 2025 packet). The title test cannot be measured the same way, because a pack's label is not always its printed title ("MA Form 1"). JK14 commits its own false-refusal count over the cached pack blanks. Its acceptance: every cached pack blank whose title block carries its year in the text layer passes, and a wrong-year blank is refused, cached or fresh. *Enforced in:* JK14 (fetch). get_form_map, fill_form and verify_form refuse a digest whose record failed it. *Extends:* the unmapped fetch function of rule 2, reading the page through pdfium's text page as locate_labels does (overlay.py:918-973). *Implemented in JK14 (2026-10-24), with two measured differences:* the tallest year counts only when it is printed at title size (at least 1.05 times the 0.63-quantile glyph height of the title block's other digits and capitals), because a prior-year blank whose title year is drawn as an image could otherwise pass on a due date; and a revision date is classified before any year comparison and refused for every tax year (Open question 7). Over the 250 cached non-draft pack blanks this passes 219 and refuses 22 as revision-dated and 9 as having no printed year. NY IT-201 and IT-203 2023-2025 are among the 9: their title year is vector art, and the only year in their text layer is the body-size tax-period line, so this acceptance sentence's "every cached pack blank whose title block carries its year in the text layer" does not hold for them.
8. **XFA-only blanks.** An /AcroForm that carries /XFA while no page carries a widget annotation is dynamic XFA: an AcroForm filler has nothing to write into. So is a blank whose catalog sets /NeedsRendering true. Both are refused with a pointer. extract_fields reads page widgets only and never looks at /XFA (packbuild.py:67-94). A hybrid (XFA plus widgets) is filled on its AcroForm layer, as the shipped AL 40 and RI 1040 packs are. Its LIMITS say that XFA bindings and form scripts do not run, so a page-header mirror stays blank unless its own widget is written (formpacks/CONVENTIONS.md:258-264; formpacks/states/ri/2024/ri1040/pack.yaml:95-124). Measured: 143 of the 348 cache entries carry /XFA, none is XFA-only, and none sets /NeedsRendering. *Enforced in:* JK14. *Extends:* packbuild.py:67-94.
9. **Scanned pages.** Anchoring reads the text layer, and a scanned image has none (overlay.py:932-934). A blank with any page that has no text layer, or whose only text is invisible (render mode 3, the layer that OCR adds over a scan), is refused with a pointer. A page with no content at all (no text, image or path object), such as an intentionally blank page, does not count. Measured on the 344 distinct cached blanks: this refuses 3: NC D-400 2023 and 2024, whose page 1 is a single image, and UT TC-40 2025, whose pages 2 and 3 carry widgets and drawn paths but no text object. Four more carry only empty pages and pass. None has an invisible-only page. ## Guardrails

ADR-0001's other fallback guardrails (verified before "done", official source and right revision, explicit LIMITS, the pack-free checks) are carried by the Decision and the refusal rules above.

### KG5: Unmapped output is never filing-grade

**Rule.** Every unmapped response carries `grade: "unmapped_draft"` at its top level, and the values worksheet carries it too. Every page of every PDF the fallback writes, the draft and the sweep, carries the stamp `UNMAPPED_STAMP = "UNMAPPED DRAFT \u2014 NOT FILING-GRADE"` (Python source; a constant beside REHEARSAL_STAMP at filler.py:592). The stamp is drawn into the page's content stream (flattened), inside the page's visible box (`visible_box`, filler.py:513-518). It lies over no widget that is visible in the written PDF. Hidden widgets do not count, among them the viewer guards that the fill hides (P-027): AL 40's viewer-guard pushbutton covers every page (filler.py:524-526). A page with no room for the stamp is refused. The stamp is not an annotation. The rehearsal stamp (filler.py:837-847) shows why. It is a pypdf FreeText annotation without the Print flag: pypdf 6.13.2 (uv.lock:694-695) sets PRINT only on a Highlight created with printing=True (pypdf annotations/_markup_annotations.py:301-302). So it does not print, and a viewer can delete it. It is also placed from the MediaBox top (filler.py:841). A page can crop a short window out of its MediaBox, as AL 40's worksheet pages do, which is why P-027 measures against the visible box (filler.py:529-532; docs/dev/HISTORY.md:2001). No parameter, prompt, environment variable or knowledge-pack state lifts the grade or the stamp. The grade consults neither `provisional_marker`, which returns None for a jurisdiction with no pack (knowledge.py:2695-2712), nor `assert_filing_grade`, which passes when that marker is None (knowledge.py:2743-2745). `ok: true` from verify never implies filing-grade.

**Where it is enforced.**
- JK16 draws the stamp with the content-stream writer the overlay already uses: `_text_op` and `_overlay_page`, merged with `merge_page` (overlay.py:282-287, :325-351, :659-661). It imports overlay lazily (routing rule 8). It writes the PDF once, already stamped. Its tests show that no parameter turns the stamp off and that every page of a print-mode render shows it. The print-mode render is pypdfium2 5.9.0 (uv.lock:703-704) with `optimize_mode="print"`, which sets FPDF_PRINTING (pypdfium2 _helpers/page.py:559-560). Its tests also rasterise the print path and OCR-read the stamp on every page, as JK16's acceptance requires (docs/dev/ROADMAP.md:356). How CI gets an OCR engine is Open question 5. The same tranche moves the rehearsal stamp into the content stream and the visible box (Open question 6).
- JK17 makes the grade a constant on every unmapped response model, with no input that changes it. verify_form fails any page without the stamp. Its checks add to the OCR check in JK16's tests; they do not replace it. It reads the stamp text in the stamp font from the text layer, as `_stamped_glyphs` reads overlay stamps (overlay.py:694-720). It measures ink in the stamp's box on a print-mode render against the same render of the blank. It reads the bitmap buffer directly, as render.py does (render.py:58), with no Pillow. It maps the box from the CropBox (`visible_box`), which is what pdfium renders. At ccf02d2 `_darkness` could not be reused: it needed Pillow (overlay.py:739), which taxfill-core does not depend on (packages/core/pyproject.toml:8-13; render.py:9-11), and it mapped the box from the MediaBox (overlay.py:738). Both were live defects on the overlay path, which calls it for checkbox ovals and minus boxes (overlay.py:753-754, :765-767): on a clean install every Hawaii N-11 check raised ImportError. JK27 (2026-10-16) fixed both (it reads the bitmap buffer and maps from the CropBox), so JK17 may reuse it. verify_form also fails a stamp whose box overlaps a visible widget. Rule 15 keeps drafts out of the pack checks.
- JK6 and JK18: the journey guard fails a fallback step without the grade, and any non-pack step that claims filing-grade (test_journeys.py:166-171). JK18 upgrades the guard for draft steps (see Consequences), and its evals hold the agent to the label.

### KG6: Safe before broad

**Rule.** Anchoring is benchmarked blind against at least 30 shipped packs, federal and state, before any tier above `low` is emitted. Two cases are mandatory and must be flagged: the ME 1040ME 2023 3-cycle on 063f293's map (the pack itself was re-bound in JK0a) and the AL 40 2023 one-high shift on its pre-P-031 keys. Every disagreement with a pack is adjudicated by a vision check before that pack counts as ground truth, because shipped maps have held rotations. The committed table reports per-field precision, counted over widgets because one field can have several, and a per-form "any mis-anchored field" rate. The benchmark passes only when the top tier reaches a measured per-field precision of at least 99% over at least 30 shipped packs, with both mandatory cases flagged and every disagreement vision-adjudicated. The top tier is worded "anchored (unverified line map)". A bare "high" never appears. The table also records the measured precision of `med`. Until the user sets a floor for it (Open question 13), fill_form treats `med` like `low`: it writes a `med` field only with a recorded confirmation. If the benchmark does not pass, the PDF fill is not built, and fill_form in unmapped mode returns the worksheet-only response (Open question 15). Benchmark fixtures use demo personas only (KG10).

**Where it is enforced.**
- JK15: the benchmark and its committed table. The anchoring code reads its tier thresholds from that table. A test fails if a tier above `low` is emitted without a passing table. get_form_map's `anchor_basis` names the table.
- JK16: without a passing table, fill_form in unmapped mode writes no PDF and returns the worksheet-only response.
- JK12: the PDF fill ships in v0.2 only if JK15 passed and the JK19 pilot report exists (docs/dev/ROADMAP.md:328). Main carries the fill from JK16, before JK19 (latest start 2027-01-11), so the condition needs a code gate. The v0.2 build packages the JK15 table only if the JK19 report is committed. Without the table, fill_form in unmapped mode writes no PDF. JK12's release check asserts this.

### KG7: No model arithmetic presented as computed

**Rule.** Every value the fallback writes or lists that no calc op produced is labeled "agent-computed, unverified" in the fill response, the worksheet, the verify response and the /TaxfillUnmapped record, whatever its kind. The server cannot see which values came from calc, so every value carries the label. No caller input removes it. `provenance` may add "from a document" or "from the user" beside it. An `independent` match is reported only in verify_form's `recompute` section, because `independent` holds what the agent says calc returned (server.py:311-314). The match changes no label, and a mismatch fails verify, as on the pack path. Whether some kinds of value may carry another label is Open question 11. The fallback never fills a ReadOnly widget, a pushbutton, a viewer guard, a signature widget or a calculated widget. A calculated widget is one whose field, read up the /Parent chain, carries an /AA /C (calculate) or /AA /F (format) action, ReadOnly or not (docs/dev/ROADMAP.md:177, :343). All of these come back as "hand-write these", with the reason. Measured: 21,267 of the cache's 49,361 text widgets (43%), on 119 of the 309 fillable entries, carry /C or /F. Counting ReadOnly widgets too, 22,557 (45.7%) are never filled. Open question 1 proposes a narrower /F clause.

**Where it is enforced.**
- JK14: extract_fields reads /Ff, /FT /Sig and /AA at field level (rule 12).
- JK16: fill_form puts those widgets in `hand_write` and labels every value.
- JK17: verify_form lists every written value with its label in `unverified_values` and runs `independent` keyed by field name.
- JK18: the skill tells the agent to label any line it computed itself, and the evals check it.

### KG11: Refuse what cannot be anchored

**Rule.** In unmapped mode fill_form refuses any value whose field has a widget anchored `none`. It refuses a value whose field has a widget anchored `low`, or `med` until the user sets a floor (KG6), unless the field is in `confirmed_fields`. A confirmation means that the user confirmed the field's boxes on the rendered sweep page (get_form_map's `sweep_path`, shown with render_form). The sweep shows the field's index on each of its widgets. Each confirmation is recorded per field, in the response (`confirmed`) and in the PDF's /TaxfillUnmapped record. Refused fields come back in `hand_write` with the value and the reason.

**Where it is enforced.**
- JK15 emits the tiers, per widget (KG6).
- JK16 refuses and records the overrides. Its acceptance plants an unanchorable widget, a calculated total, and a field with one anchored and one unanchored widget. All three must land in `hand_write`.
- JK17: verify_form re-derives the anchors from the blank named by `blank_sha256`. It fails a written field with a widget anchored `none`, or anchored `low` (or `med`, KG6) without a recorded confirmation. A direct core call cannot skip the rule.
- JK18: an eval checks that the agent shows the sweep page before it asks the user to confirm a box.

## Open questions

1. **KG7 and format actions (a proposed amendment).** The KG table (docs/dev/ROADMAP.md:177), the JK14 box (:343) and ADR-0001's KG7 row count any /AA /F (format) action as calculated. The user decides whether a declared kind of value may carry another label instead. Until then `provenance` only adds a source beside the label. The ROADMAP says the fallback labels part-year allocation lines as agent-computed (docs/dev/ROADMAP.md:408); the rule covers them.
12. **verify_filing.** The ROADMAP does not say whether verify_filing takes unmapped items. This ADR refuses them (rule 15). Revisit after JK19 if the pilot needs filing-level checks.
13. **A floor for `med`.** KG6 sets a measured floor only for the top tier, and KG11 lets fill_form write a `med` value with no confirmation. So `med` could fill unconfirmed at any precision. This ADR treats `med` like `low` until the user sets a floor from the measured `med` precision in the JK15 table.
14. **Partly scanned blanks.** Rule 9 refuses a blank if any page with content has no text layer, as the ROADMAP says (docs/dev/ROADMAP.md:339, :344). Filling the text pages of such a blank, with every widget on a scanned page in `hand_write`, would serve more forms. The user decides.
15. **When the benchmark fails.** The ROADMAP says that then "JK16 is skipped and the fallback ships inspect + worksheet only" (docs/dev/ROADMAP.md:351). For a blank with no pack, only fill_form can return a graded worksheet: hand_fill_worksheet needs a hand-fill pack. So this ADR reads "JK16 is skipped" as "the PDF fill is not built", and builds fill_form's worksheet-only response in JK16's place. The user confirms this reading, or keeps JK16 out entirely; the fallback then ships inspect only.
16. **Which page is "page 1".** The JK14 box asks for "the page-1 printed year and title" (docs/dev/ROADMAP.md:344). Rule 7 reads the form's first page, the first page that carries a widget, because a packet can open with instructions or a cover note. Measured: for 43 of the 298 packs, the first widget of the cached blank is not on page 1. 30 are IRS early-release drafts, whose page 1 is a cover note, and 13 are packets (Form 1040-ES, LA IT-540, NC D-400 and OK 511). The user confirms the reading.
17. **Wording conflicts.** This ADR proposes a reading; the user confirms it. JK15's box says "high, med, low or none"; KG6 says never a bare "high". This ADR follows KG6. ADR-0001 says the grade appears in "every response field"; the JK13 box says "every response". This ADR puts it at the top level of every unmapped response and on the worksheet.

## Decisions (2026-10-25)
